# บทที่ 1 — รู้จักบอร์ดก่อน flash

> บทเรียนนี้แพงที่สุดในคอร์ส: เรา flash firmware ผิดบอร์ดไป 2 รอบ
> ได้ boot loop มา 1 อัน กับเวลาที่หายไปหลายชั่วโมง

## เรื่องที่เกิดขึ้นจริง

Waveshare ขายจอ 7 นิ้วสองรุ่นที่หน้าตาแทบแยกไม่ออก: **ESP32-S3-Touch-LCD-7**
(800×480, ใช้ CH422G เป็น I2C IO-expander) กับ **ESP32-S3-Touch-LCD-7B**
(1024×600, ใช้ CH32V003 — MCU RISC-V ทั้งตัวที่รัน firmware ทำหน้าที่ expander)

เราเชื่อสเปกชีตกับชื่อรุ่น เลย flash config ของ 7B ลงบอร์ดที่จริง ๆ เป็นรุ่น 7 ธรรมดา
โค้ด init คุย I2C กับ CH32V003 ที่ไม่มีอยู่จริง บอร์ดก็เข้า boot loop ทันที
(บันทึกไว้ที่ `e254a4a` และ memory `id-the-board-before-flash.md`)

ที่เจ็บกว่านั้น — เอกสารของ Waveshare เองหน้ารุ่น 7B ยังเขียนว่าใช้ CH422G
ซึ่งผิด เพราะ copy มาจากหน้ารุ่นเก่า เชื่อ vendor doc อย่างเดียวก็โดนอยู่ดี

## หลักการ

**ระบุตัวตนบอร์ดจากหลักฐานบนตัวมัน ไม่ใช่จากชื่อรุ่นหรือสเปกชีต** เรียงตามความน่าเชื่อ:

1. **Firmware ที่รันอยู่แล้ว** — ถ้าบอร์ดเคยมี firmware ที่ทำงานได้ อ่าน log ของมันก่อน
   มันจะบอกเองว่า init อะไรสำเร็จ นั่นคือใบรับรองที่ปลอมไม่ได้
2. **Silkscreen บน PCB** — เลขรุ่นที่พิมพ์บนบอร์ดจริง เช่น WT32-SC01 Plus
   เราระบุได้จากคำว่า `ZX3D50CE08S-V14` บนหลังบอร์ด ไม่ใช่จากชื่อที่ร้านตั้ง
3. **USB descriptor** — `pio device list` แล้วดู VID:PID
   `303A:1001` คือ Espressif native USB, `1A86:xxxx` คือ CH343 UART bridge
   ตัวเลขนี้บอกได้ด้วยว่าเสียบพอร์ตไหนอยู่ (สำคัญ — ดูหัวข้อถัดไป)
4. **MAC address ของชิป** — `esptool chip_id` ให้ค่าที่ไม่เปลี่ยนตาม replug
   ต่างจากชื่อพอร์ต `usbmodemXXXX` ที่สลับได้ทุกครั้งที่ reset

ข้อ 4 มีเรื่องจริงรองรับ: ตอนต่อบอร์ด S3 สองตัวพร้อมกัน เรา flash ใส่บอร์ดผิดตัว
อยู่ ~20 นาที เพราะชื่อพอร์ต shuffle หลัง reset — ตั้งแต่นั้น map พอร์ตกับ MAC
ก่อนแตะอะไรทุกครั้ง

## กรณีพิเศษ: บอร์ดสอง USB-C

Waveshare 7 มี USB-C สองพอร์ตที่หน้าตาเหมือนกันเป๊ะ แต่พฤติกรรมคนละโลก:

| พอร์ต | ชิป | Flash | เห็น panic log |
|---|---|---|---|
| native USB | ESP32-S3 USB-Serial-JTAG | auto-reset ได้ | เฉพาะเมื่อ logger ชี้ `USB_SERIAL_JTAG` |
| UART bridge | CH343 | ต้องกด BOOT+RESET เอง (macOS ขับ DTR/RTS ไม่ได้) | เฉพาะเมื่อ logger ชี้ `UART0` |

เสียบผิดพอร์ตจะเจอ `No serial data received` ทุกครั้ง — ไม่ใช่บอร์ดพัง แค่ผิดรู
และถ้า firmware boot loop จน native USB ไม่ตอบ: กด BOOT ค้าง แตะ RESET
ปล่อย BOOT แล้ว flash ด้วย `esptool --before no_reset`

## กรณีพิเศษ: SKU เดียวกัน ของข้างในไม่เหมือนกัน

Waveshare 2.8B ของเราให้ `Calibration error` ตอน init GT911 ตลอด
ไล่ debug สาย I2C อยู่นานก่อนพบว่า SKU ที่ซื้อมาเป็นรุ่น **ไม่มี touch**
— feature ที่ debug อยู่นั้นไม่มีตัวตนบนบอร์ด ตรวจ suffix รุ่นจากหน้าสินค้า
ให้เห็นก่อนเริ่มไล่บั๊กของที่อาจไม่มีอยู่จริง

## เช็กลิสต์ก่อน flash ครั้งแรก

- [ ] เห็น silkscreen รุ่นบนบอร์ดจริงแล้ว
- [ ] รู้ว่า expander เป็นตัวไหน (CH422G / CH32V003 / TCA9554 / ไม่มี)
- [ ] map ชื่อพอร์ต ↔ MAC/VID:PID แล้ว (สำคัญมากถ้าต่อหลายบอร์ด)
- [ ] รู้ว่าพอร์ตที่เสียบคือ native USB หรือ UART bridge
- [ ] มี firmware อ้างอิงที่รู้ว่าติดจอได้ ไว้ flash ทดสอบแยกฮาร์ดแวร์ออกจากโค้ด

ข้อสุดท้ายคือท่าไม้ตายของบทที่ 5: จอดำ 15 รอบ reflash จะจบเร็วมาก
ถ้าเริ่มจาก "flash ของที่เคยติด" — ติดแปลว่าบั๊กอยู่ในโค้ดเรา ไม่ติดแปลว่าดูฮาร์ดแวร์
